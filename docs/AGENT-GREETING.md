# 开场白设计

**受众假设**:技术验证的演示对象与验收方,不是临床医生。若受众改为医生,本文件需重写(措辞要从"可核验"转向"能不能用在我手里的病人身上")。

开场白分两层。**静态层只说不会变的事,动态层才说本次会话判得了什么。** 混成一层就会在 GraphDB 挂掉的会话里撒谎。

---

## 一、静态层:载体欢迎语

写死在 UI(Dify opening statement / `demo/` 首屏 / README 顶部),模型看不见。**只承诺常量**:身份、只读、三条硬禁令、非医疗器械、以及"我会先自检"。**不列具体能力项,不列检验项名,不列 IRI 样例。**

> **糖尿病本体 × 患者事实库 · 证据型问答**
>
> 我只回答能在本库里找到出处的问题:患者事实、阈值判定、风险分层、用药安全信号、术语映射、图谱关系、他人结论与引用的裁决,以及「若 X 则 Y」的确定性推演。每条结论都带规则号、逐字原文和哈希,你可以当场核。
>
> 三件我不做:**不给药物剂量,不给风险概率或时间窗,不替代诊断**——这是技术验证服务,不是医疗器械。
>
> 查不到的时候,我会告诉你**为什么查不到**,而不是替你补一个像样的答案。
>
> 你问第一个业务问题时,我会先自检一次数据源,并告诉你这一版图谱究竟判得了哪些检验项。

### 更短的一句版(用于窄栏/标题位)

> 带出处的糖尿病问答。每条结论可回溯到规则号与原文;判不了的时候我会说判不了,不会猜。

---

## 二、动态层:首轮自检卡片

触发时机:会话内第一个业务问题。由 `GET /health` + `GET /agent/manifest` 的返回体渲染,**槽位一律原样填,不改写、不四舍五入、不省略降级说明**。

```
【数据源】postgres {ok} · graphdb {ok} · graphVersion {graphVersion}
【可判定边界】本版挂了阈值的检验项共 {n} 项:{test}({units}{,需复核 if confirmationRequired})…
             不在这张表里的检验项本库判不了。我会直接说判不了并给出理由,不逐个去试。
【术语缺口】未映射 {unmappedTerms} 条;查得到但判不了 {labTermsNotUsable} 条
【免责声明】{disclaimer 原样}
```

卡片之后直接回答用户那个问题,**不要停下来等确认**。

### 三种降级形态

| 情形 | 开场怎么说 | 后续可用范围 |
|---|---|---|
| `graphdb.ok=false`(503) | 明确报 graphdb 的错误原文,声明**图侧结论全部停止** | 只剩 SQL 事实层;语义/图/出处/裁决/推演层一律不进 |
| `postgres` 侧读取失败(manifest 返回 `degraded`) | 原样复述 `degraded` 那句话,说清缺的是概念计数与术语缺口 | `assessableLabTests` 来自 GraphDB **仍然有效**,患者事实层不可用 |
| 两侧都挂 | 只报服务状态,**不进任何业务分析**,不用常识生成替代结论 | 无 |

### 同一会话中 `graphVersion` 变了

重新渲染一次卡片,并明说:**先前的术语映射、规则和结论全部作废,需要重新查询。**

## 三、预设问题(suggested questions)

比开场白正文更重要——用户会点,而点击决定了他对这个系统的第一印象。四条按「边界 → 事实 → 出处 → 裁决/推演」排,每条都演示一项别的问答系统给不出的东西。

1. `现在数据源通不通?这一版能判定哪些检验项?`
2. `列出前 10 位患者,并标明哪些是真实事实、哪些是演示数据`
3. `患者 <PID> 的风险分层是哪一档?凭哪条规则、原文哪一句?`
4. `「患者 <PID> 的 A1C 已达糖尿病诊断切点」这个说法成立吗?帮我裁决`

第 5 条可选(推演层,需用户自己填数值,不要预填):

5. `若患者 <PID> 在 <日期> 补一次 <检验项> = <值> <单位>,结论会变吗?`

**第 2 条和第 4 条是这个系统的招牌**:真实/演示不混、以及"别人的结论我也能判"。只放能力介绍不放这两条,演示会平淡得像个普通 RAG。

---

## 四、开场白的禁止项

1. **不列 IRI 样例。** 见 `src/dmo/manifest.py:_ontology_overview` 的注释:调用方看见 IRI 就会照着拼,拼错查出来是空集,和"没有数据"长得一模一样。要 IRI 只有一条路——`GET /graph/concepts`。
2. **不静态罗列具体能力项和检验项名。** 那是 `assessableLabTests` 的活,它每版都会变。
3. **不写成免责声明墙。** 声明超过两句话,读者就一句都不看了,反而更危险。三条硬禁令 + 一句"非医疗器械"到此为止。
4. **不用背书式措辞。** "已通过医学验证""权威""安全"一律不出现——这条在最高优先级规则第 12 条里。
5. **不说"我能回答任何糖尿病问题"。** 这个系统的价值恰恰在它敢说自己判不了。
