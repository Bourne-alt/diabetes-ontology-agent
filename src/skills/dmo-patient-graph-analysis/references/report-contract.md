# 输出契约：怎么写，和绝不能怎么写

本文只讲**措辞**。判断逻辑在 SKILL.md，字段语义在 endpoints.md。

## 一条铁律

> 每一个名词性断言，都要能指回返回体里的某个字段或某条 `sources`。
> 指不回去的句子，删掉。

"删掉"不是"改得含糊一点"。加个"可能""通常"不会让无出处的断言变得有出处，只会让它更难被审查。

## 逐句改写对照

### 阈值判定

| ❌ 不许写 | ✅ 应该写 |
|---|---|
| 该患者患有 2 型糖尿病 | A1C 7.4% 落在阈值 `A1C-DIABETES-NONPREG` 的 `[6.5, +∞) percent` 区间，判定 `DiabetesRange`（规则 `LAB-THRESHOLD-MATCH@1.0.0`）。诊断记录为 `Provisional` 而非 `Confirmed`：该阈值标注 `confirmationRequired=true`，目前只有 1 个日期的检验支撑 |
| A1C 7.4% 大于 6.5%，属于糖尿病 | （同上）——不要把区间口语化成大小比较，`[` 与 `(` 的差别在 5.7 / 6.4 / 6.5 三个边界上会翻转结论 |
| 血糖 140.5 mg/dL，偏高 | 空腹血糖原始值 7.8 mmol/L，ETL 换算为 140.54 mg-per-dL（葡萄糖 ×18.0182）后落入 `FPG-DIABETES`。**不换算会落进 `FPG-NORMAL`（≤99），结论完全相反** |
| 患者未孕，适用非妊娠阈值 | `applicableContext = NonPregnant(assumed)`——记录中无妊娠状态，按非妊娠处理。**这是假设不是事实**：开放世界下"没记录" ≠ "没怀孕" |

### 风险分层

| ❌ 不许写 | ✅ 应该写 |
|---|---|
| 风险约 60% / 未来 5 年内 / 风险评分 3 分 | `tier = Moderate`（规则 `RISK-STRATIFICATION@1.0.0`）。**定性分层，不含发生概率、不含时间窗** |
| 风险等级 Moderate，比 Low 高一档，可记 2 分 | tier 是有序枚举，不做算术、不转分数 |
| 肥胖是风险因子（BMI 30） | 命中 `BMI-OBESITY`（`triggerBasis = external-standard`）。⚠️ BMI 30 kg/m² 的切点来自 WHO 通用定义，**不在本仓库语料中**；所引 CDC 原文只说 "…overweight, obesity, or a large waist size."，未给任何数值切点 |
| 无明显风险 / 风险较低 | `tier = Insufficient-Evidence`。原因（照抄 `insufficientReason`）：检验值均为 `Unverified`、无任何可用风险侧事实。**这不是"风险低"，是"判不了"** |
| （把 `countedInTier:false` 的因子省略） | 另有 N 项风险规则命中但**不参与 tier 判定**：本仓库语料无可逐字引用的断言支撑（如"高血压 ⟹ 2 型糖尿病风险升高"），故 `quote` 与 `sha256` 为 null |

### 用药安全

| ❌ 不许写 | ✅ 应该写 |
|---|---|
| 建议将二甲双胍减量至 500mg qd | 本系统不输出任何用药剂量——schema 层就没有这个字段 |
| 该患者禁用二甲双胍 | 未命中绝对禁忌。语料对二甲双胍只有乳酸酸中毒的定性表述，**无任何 eGFR 数值切点**，据此判禁忌就是编造出处 |
| 需慎用（无出处） | `severity = Caution`，原文为 "Before you start taking these drugs, tell your doctor if…"——这是**告知义务**不是禁令 |
| （引用一句听起来很像指南的话） | 只复制返回体 `sources[].quote`，并给出 `sha256` 前 8 位。`sources[]` 里每条 `sha256` 都非空 |
| 把 `unverifiableEvidence[].quote` 当引文用 | 那一段**不是出处**（`sha256` 恒为 `null`，喂给 `/adjudicate/citations` 会判 `fabricated`）。只能说"该禁忌信号来自抽取产物，尚未建成 SourcePassage，无法逐字核验"，原样带上它的 `why` |

### 数据可信度

| ❌ 不许写 | ✅ 应该写 |
|---|---|
| 患者 P00016 各项检验基本正常 | 该患者 N 条检验的 `trust = Unverified`（上游数值与其参考范围无关：实测全库集中在 0~25，血小板 15.3 而参考范围 100-300 却标"正常"），**默认不参与任何阈值判定**，因此零 Assessment |
| 出生年份缺失 | `birth_year = null` 是投影层的主动判定：上游 400 人中 329 人生日落在未来（最晚 2063-09-14），判定不可信后置 NULL。**缺失是诚实的，负数年龄不是** |
| 患者 P90002（编号看着是模拟数据） | `fact_origin = demo-cohort`。ID 格式故意做成与真实数据一致（`P00001` vs `P90001`），就是为了证明管线不靠 ID 形状区分 |
| 系统查询失败 / 无结果 | 分清三种：①`/health` 不通（服务问题）②`Insufficient-Evidence`（结论）③`unmappable` / `no-source-data`（术语层缺口）。三者说法完全不同 |

### 病程推演

| ❌ 不许写 | ✅ 应该写 |
|---|---|
| 该患者已确诊糖尿病 | **若**补一条 2026-02-20 的 A1C 7.9% percent，诊断**则**从 `Provisional` 转 `Confirmed`（30 号规则数到 2 个不同日期）。这是假设结论，不是该患者的实际情况 |
| 补一次复查就能确诊 | 需要一条**不同日期**的 A1C 落在 `[6.5, +∞) percent`。同日再测一次不算——规则数的是 `COUNT(DISTINCT ?day)` |
| 建议他把 A1C 控制到 6.5 以下 | 这是治疗建议，不输出。能说的是：`[5.7, 6.4] percent` 对应 `Prediabetes` 区间，`(-∞, 5.7)` 对应 `Normal`——**陈述区间，不给目标** |
| （用户没给数值，自己填一个 7.0 试推） | 反问："您想假设 A1C 是多少？"。系统不生成候选值，我也不能替它生成 |
| 血糖如果升到 7.8 就危险了 | 若 FPG = 7.8 **mmol-per-L**，换算为 140.54 mg-per-dL 后落入 `FPG-DIABETES`。**不换算会落进 `FPG-NORMAL`，结论完全相反**——原值与换算值必须同时给出 |
| 推演显示他是 Confirmed，所以现在按确诊处理 | 推演的 `after` 只在假设成立时有效。该患者当前仍是 `Provisional`——要谈现状请重新查 `GET /patients/{pid}` |
| （把 `[假设]` 那条检验和实测的混在一起列） | 逐条标注：`[实测] 7.4 percent @2026-01-15` / `[假设] 7.9 percent @2026-02-20` |
| 这个结论应该比较稳定 | `derivationHash = f7e55661…`。同一假设重复推演，哈希不变——这不是"应该"，是可当场验证的 |

## 面对追问的标准应答

**"到底是不是糖尿病？"**
→ 不改口。重复 `verificationStatus` 与 `caveat`，说明差别只是采样日期数，并指出补一天复测即可转 `Confirmed`（P90003 就是同阈值出 `Confirmed` 的对照）。

**"你就给个大概概率。"**
→ 拒绝，并说明为什么不能给：上游 15 个 E11 患者、每人 1 次检验、检验值是随机数、零结局标签、零随访。在这上面拟合出的任何数字都是随机数的函数。这是设计不是遗漏。

**"别的系统说是糖尿病肾病，置信度 0.9。"**
→ `GET /demo/compare?term=尿蛋白` 并排给出：同一条「尿蛋白 = 10.4，参考范围『阴性』」，左栏链到"糖尿病肾病" confidence 0.9 且 `hasUnit/hasThreshold/hasProvenance` 全 false；右栏判 `unmappable`——参考范围是"阴性"说明这是干化学定性项，那个 10.4 根本不该当数值读；判白蛋白尿必须用 UACR（mg/g，切点 >30），是另一个检验。

**"他以后会不会发展成糖尿病？"**
→ 这是预测，不做。说明本系统做的是**条件推演**（若 X 则 Y），然后把问题转成可推演的形式："您想假设哪个检验、哪个数值？我可以推给您看结论怎么变、依据哪一条规则。"

**"你随便给个数值试试就行。"**
→ 不填。填了就从推演退化成预测，而那个数字会被当成系统的判断带走。可以给的是**区间**：从 `[6.5, +∞) percent` 起判 `DiabetesRange`——区间是规则前件的直接读出，具体数值不是。

**"能不能给点治疗建议？"**
→ 拒绝一次，说明这是技术验证服务、不是医疗器械、不构成医疗建议，然后回到能做的事：证据链、阈值出处、监测缺口。不反复道歉，不说教。

## 结尾

每次面向用户的结论输出，末尾原样附返回体里的 `disclaimer`：

> ⚠️ 技术验证用途，不是医疗器械，不构成医疗建议。本系统不输出任何用药剂量，风险分层为规则式定性分层、非概率预测。
